# keri-http-auth

KERI HTTP message signatures and request authentication in Rust: the `Signature` and
`Signature-Input` headers, the exact bytes a signature covers, and the `Signify-Timestamp` header.
The behavior and wire bytes match [signify-ts](https://github.com/WebOfTrust/signify-ts), checked
against fixtures it generates, and the header formats are the ones keripy and KERIA speak.

Extracted from the signify-rs project.

## Modules

| Module | Purpose |
|---|---|
| `header` | Validated header names and values, and a bounded collection that refuses duplicates |
| `fields` | The `Signature` header: signages, markers and parameters, formatted and parsed strictly |
| `input` | The `Signature-Input` header and the signature base it describes |
| `authentication` | `RequestSigner` signs a request; `ResponseVerifier` checks a response |
| `timestamp` | The `Signify-Timestamp` header value |

A Signify client uses all five to sign what it sends to a KERIA agent and to verify what comes
back. The parsers and the signature base are the same ones the agent needs on its side; signing a
response and verifying a request are not provided yet.

Freshness is not decided here: `created` is returned to the caller, and replay policy belongs to
the transport.

## Use

```bash
cargo add keri-http-auth
```

```rust
use keri_cesr::crypto::salt::{Salt, SecurityTier};
use keri_cesr::crypto::verifier::KeyTransferability;
use keri_http_auth::authentication::RequestSigner;
use keri_http_auth::header::{HeaderName, HeaderValue, Headers};
use keri_http_auth::input::{RequestTarget, default_components};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let salt = Salt::from_raw(b"0123456789abcdef", SecurityTier::Low)?;
    let signer = RequestSigner::new(salt.derive_signer("", KeyTransferability::Transferable)?);

    let headers = Headers::from_pairs([
        (
            HeaderName::new("signify-resource")?,
            HeaderValue::new("EWJkQCFvKuyxZi582yJPb0wcwuW3VXmFNuvbQuBpgmIs")?,
        ),
        (
            HeaderName::new("signify-timestamp")?,
            HeaderValue::new("2022-09-24T00:05:48.196795+00:00")?,
        ),
    ])?;

    let input = signer.signature_input(default_components()?, 1_609_459_200)?;
    let signed = signer.sign(&input, &RequestTarget::new("POST", "/boot")?, &headers)?;

    let mut request_headers = headers;
    signed.apply(&mut request_headers)?;
    assert!(request_headers.get("signature-input").is_some());
    Ok(())
}
```

## Prerequisites

- Rust 1.97 or newer (`rustup` installs the toolchain pinned in `rust-toolchain.toml`).
- Nightly Rust and `cargo-fuzz`, only for fuzzing.
- Node 22 or newer, only to regenerate the fixtures.

## Build and test

```bash
cargo fmt --all -- --check
cargo clippy --all-targets
cargo test
cargo deny check
```

## Reference fixtures

`fixtures/` holds the expected outputs, generated by signify-ts at the commit pinned in
`tools/reference-vectors/package.json`. Tests read them and never need Node or the network.
Each fixture directory has a README with its provenance.

```bash
npm ci --prefix tools/reference-vectors
npm run --prefix tools/reference-vectors check      # regenerate and fail if anything changed
npm run --prefix tools/reference-vectors generate   # regenerate after an intended change
```

## Fuzzing

```bash
cargo +nightly fuzz list
cargo +nightly fuzz run authing
```
